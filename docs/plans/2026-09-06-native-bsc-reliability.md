# BSC 收款可靠性源码修复计划

日期：2026-09-06。研究基线：本地 main `9be4367`，生产官方镜像 `v1.24.2-4d88040`。
状态：源码修复、测试、正式部署及外置服务撤除完成。新付款实际到账验收尚未发生，不以空闲状态或只读检查代替。

## 目标与边界

让 BEpusdt 原生完成合约过滤、RPC 选择、交易确认、历史补查及失败恢复，移除 BSC 外置 Python RPC 适配器。
本次仅 BSC 启用新的 RPC 和持久化扫描分支，其他链保留原调度、不擅自改节点；通用订单 CAS 与回调保护共享。不改变付款金额、签名协议和收款钱包。
NewAPI 前面的等待状态回调适配器是另一项兼容需求，单独验收和撤除，不能因 BSC 修好就一并删除。
保持 Go 单进程及现有 SQLite/PostgreSQL 模式，不引入 Redis、消息队列或新的常驻服务。

## 已确认的问题

## 实施顺序

### 1. 原生 RPC 调用及合约过滤（P0）

修改 `app/task/evm.go`，新增小范围 `app/task/evm_rpc.go`；复用 `app/model/registry.go` 的链与合约注册信息。

- 使用结构体和 `encoding/json` 构造请求。按当前网络提供支持的非原生币合约地址列表，去重、统一小写。
- BSC 自动携带 USDT/USDC 合约过滤，保留钱包监控和 MQTT 支持范围；不要只过滤当前待付款订单而漏掉其他有效监听。
- 增加可选 BSC 区块/回执节点与备用节点列表；现有 `rpc_endpoint_bsc` 保持兼容，继续作为日志节点。
- 后台可直接配置这些字段，沿用现有配置缓存刷新机制。缺省时沿用旧节点，迁移时显式设置生产节点，不静默覆盖用户配置。
- 启用节点前校验 `eth_chainId=56`，分别验证区块读取、带合约日志、已知历史回执；能力判定按节点、方法记录。
- 分类 HTTP 429/5xx、JSON-RPC 错误、权限限制、方法不支持、空结果和非法响应。权限不支持时切换适用节点，不对原节点立即无限重试。
- 单次请求和整个任务各有超时预算，排队计入总预算；确认保留独立并发额度，不等待历史扫描释放全局锁。
- 严格校验批量响应的 ID、数量、区块号和时间戳。HTML、缺项、null 不能当成无交易成功。
- 校验 topic、地址、data 的十六进制长度，避免直接字符串切片 panic；按网络校验合约，金额保持整数与 decimal 精度。

### 2. 原生确认与历史日志兜底（P0）

- `eth_getTransactionReceipt` 优先使用支持历史回执的读取节点；验证 hash、区块、成功状态及实际 Transfer 日志中的合约、接收地址、金额。
- 原生 BNB/ETH 不要求 ERC20 日志：核验交易 hash、to、value、区块及成功回执；代币与原生币分开验证。
- 在交易时间符合订单有效期的前提下继续确认；订单时间过期或 RPC 不可用不能被误判为链上支付失败。
- 明确处理 `status=0x0`、`result=null`、链重组/区块不一致和确认数不足。临时不可用保留待确认，按退避重试并展示原因。
- `eth_getLogs` 被历史权限限制时，先尝试配置的兼容日志节点；仍不可用才使用 `eth_getBlockReceipts` 恢复小区块范围日志。
- 沿用每批最多 10 个区块；校验每个区块响应完整性，按合约、topic 过滤，统一进入现有订单匹配管道。
- 如果节点不支持 `eth_getBlockReceipts`，只允许有界的逐交易回执降级或要求配置历史节点；绝不返回伪造空列表吞掉缺口。
- 节点限流/失败期间不能生成任何成功付款记录。回执恢复只是读取链上数据，不直接补余额。

### 3. 有界重试、持久化补查和正确完成水位（P1，上线撤脚本前完成）

修改 EVM 调度及回溯逻辑，必要的任务状态使用项目现有数据库保存，不另加服务。

- 实时扫描、订单确认、历史回溯分别限并发；限流等待不持有网络 I/O 的全局互斥锁。
- 区块范围任务去重，包含 attempt、next_retry_at；指数退避、随机抖动并遵循 Retry-After。
- 限制在途及内存任务数量，数据库每订单最多一条补查记录。读取任务和候选订单分页，持续失败采用有上限的退避并保存诊断，不能丢弃任务或资金记录。
- 保存补查目标范围和连续完成位置，启动时恢复未完成任务；仅观察到最新高度不代表此前区块处理完成。
- 回溯阶段区分 pending/running/completed/failed；只有范围内所有区块成功处理后才 completed。
- 完成边界必须是转账已持久化到事件收件箱，或订单匹配已提交；放入内存 transferQueue 不算完成。事件以链、交易 hash、logIndex（原生转账使用独立标识）去重。
- 已建立补查任务必须固定关联订单，重试超过三小时后仍可匹配这些订单；交易时间仍严格受原订单有效期约束，不能将迟到付款自动入账。
- BSC 不再依赖外部高度服务，直接使用当前链 RPC 时间戳指数定位加二分查询；非法范围、超时和背压仍保留任务。
- 固定任务快照时间 T，回溯结束取所有关联订单 min(ExpiredAt, T) 的最大值，避免过期订单缩短仍有效订单的窗口；处理完当前区间后接续新产生区间。
- 优先对 EVM 接入新的补查接口；不要直接改变共享函数使 Tron、TON、Solana、Aptos 行为跟着变化。
- 若使用新增表，采用现有 migration 机制且只做增量兼容结构。回滚旧二进制时保留运行期间新产生的订单数据。

### 4. 订单状态与回调可靠性（P1，上线撤脚本前完成）

修改 `app/model/order.go`、`app/task/transfer.go`、`app/task/notify.go`、`app/task/notify/notify.go`。

- 订单成功使用带预期状态及 ref_hash 的条件 UPDATE，返回数据库错误与 RowsAffected；仅首次成功转换触发成功通知。
- MarkConfirming 同样必须 CAS，只允许等待或过期订单转换，不能覆盖已确认、成功、取消或失败订单。重复事件不触发二次状态转换。
- 通知状态只更新通知字段，防止整行旧快照覆盖订单成功状态。所有付款终态变更统一沿用条件更新规则。
- 利用现有 success + notify_state=0 的数据库重试能力，保证提交成功后进程退出也可补发；不承诺网络层恰好投递一次。
- 按订单串行投递/占用任务，合并立即发送与定时重试；HTTP 请求期间不占用数据库事务。
- 终态回调要求 HTTP 200 且响应体 trim 后忽略大小写严格等于 ok 或 success，兼容两份现有文档；fail、错误 JSON 及包含这些词的其他内容不能算 ACK。等待/过期通知保留现有协议。
- 等待状态通知的禁用按明确回调 URL 配置，默认不禁用；只关闭当前 NewAPI 目标，不改变其他商户。
- 覆盖“接收端已入账但响应丢失”情形：允许重复回调，但接收端按订单幂等入账。
- 区分等待状态通知、支付成功通知及商户 ACK，日志不再用同一个“成功”让人误认付款完成。

### 5. 后台与故障可见性（P1）

修改 `app/conf/stat.go`、`app/handler/admin/conf.go` 和 `web/src/views/system/rpc/rpc.vue`，并为订单详情提供必要诊断字段。

- 扫描成功统计仅在区块、日志校验及后续交付完成后记录，每次任务结果计数一致。
- 展示链头、连续完成高度、落后区块数、重试队列、最久待确认时间。
- 展示当前节点及用途、最近 HTTP/RPC 错误和最后成功确认时间；节点密钥必须脱敏。
- 无订单且未启用其他监听时显示空闲，而不是默认 100% 成功；扫描正常不等于回调正常。
- 订单详情分开显示链上匹配、链上确认、商户通知状态及各自失败原因。

### 6. 验证、部署与撤除脚本

自动化测试：沿用 `httptest` 和临时 SQLite，网络故障使用固定响应构造，不依赖公网节点作为 CI 判断依据。

- 合约过滤、日志解析、历史权限拒绝后的节点切换、回执恢复以及缺失批量结果必须有测试。
- 429、503、超时、错误链 ID、null 回执、回执失败、区块 hash 不一致均不能确认收款。
- 扫描队列饱和时确认请求仍能处理；断网后队列有界，恢复后补齐缺口。
- 回溯被中断或进程重启不会永久标记完成，不漏掉尚未处理的区间。
- 并发确认、回调超时、数据库写失败、接收端已入账后断连，不会触发重复资金记账或订单状态回退。
- 使用脱敏的订单 196 数据构造“匹配成功 -> 回执权限失败 -> 备用节点确认 -> NewAPI ACK”完整场景。
- 使用订单 191 类场景覆盖“订单过期但实际付款在有效期内，恢复后补查”；不得重复充值已经人工补单的 NewAPI 订单。
- 执行 `go test ./...`、相关包 `go test -race`，构建后端与现有前端生产包。

生产切换：

1. 备份镜像、完整配置、数据库，明确旧版本回滚方式。
2. 用隔离数据库和本地模拟商户回调验证升级，不允许两实例同时监听生产钱包并通知生产 NewAPI。
3. 设置源码版的真实 RPC 地址，清除 BSC 配置对 `172.18.0.1:18545` 的依赖。部署固定版本镜像。
4. 核验真实回执、历史漏查与故障恢复；真实付款验收使用用户批准的小额订单，检查 NewAPI 账本而非只看 HTTP 200。
5. 验证 BEpusdt 已无外置 RPC 访问后停用 `bepusdt-bsc-rpc-adapter.service`，保留备份到观察期结束。
6. 长时间观察并注入故障，覆盖历史查询年龄限制；短时间 100% 不能作为最终可靠性结论。

另一个 `bepusdt-callback-adapter` 的撤除条件：为 BEpusdt 增加默认空列表的按回调 URL 禁用等待通知配置；仅当前 NewAPI 目标关闭 status=1 通知，核验签名和终态 ACK 后，将两台 NewAPI Nginx 的 webhook 路由切回 NewAPI，再停适配服务。成功与过期通知不能随手屏蔽。

2. `fix: make EVM scan retries and lookback resumable`：第 3 阶段、修正统计与相关迁移。
3. `fix: protect payment state transitions and callback acknowledgements`：第 4 阶段与支付链路测试。
